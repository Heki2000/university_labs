## 📄 Формат входного файла `todos.json`

Файл должен быть сохранен в кодировке UTF-8 и содержать JSON-массив объектов. Каждый объект обязан иметь следующие поля:

* `id` — положительное целое число, уникальное в пределах файла;
* `userId` — положительное целое число (идентификатор пользователя);
* `title` — непустая строка (название задачи);
* `completed` — логическое значение (`true` или `false`).

Содержимое используемого `todos.json`:

```json
[
  {"id": 1, "userId": 5, "title": "Ввод", "completed": true},
  {"id": 2, "userId": 5, "title": "Циклы", "completed": false},
  {"id": 3, "userId": 10, "title": "Строки", "completed": true},
  {"id": 4, "userId": 10, "title": "Файлы", "completed": true},
  {"id": 5, "userId": 5, "title": "Списки", "completed": true}
]
```

## 🌐 Пояснения по HTTP (Сетевое упражнение)

В файле `fetch_profile.py` реализовано получение профиля пользователя GitHub.

* **Адрес:** `https://api.github.com/users/<login>` — официальный API GitHub. Мы запрашиваем именно профиль пользователя, а не репозиторий.
* **Метод GET:** Используется для безопасного чтения данных ресурса без его изменения на сервере.
* **Таймаут (`timeout=10`):** Ограничивает время ожидания ответа сервера. Если сервер не ответит за 10 секунд, программа выбросит `TimeoutError` и не зависнет.
* **Заголовки:** `Accept` сообщает серверу, что мы ждем JSON, а `User-Agent` предотвращает блокировку запроса со стороны GitHub.
* **Обработчики ошибок:**
  * `HTTPError` — обрабатывает ответы сервера с кодами 4xx/5xx (например, 404 — пользователь не найден).
  * `URLError` / `TimeoutError` — сетевые проблемы (нет интернета).
  * `ValueError`, `UnicodeError` — если ответ не похож на профиль или повреждена кодировка.
  * `OSError` — ошибки при сохранении файла `profile.json`.

  *(Примечание: если при проверке в сети университета сервер возвращает 403 Forbidden из-за лимитов IP, это нормально. Скрипт корректно обработает ошибку и выведет сообщение.)*

## 🧠 Дополнительные объяснения (Для защиты)

* **Почему используется `with open()`?** Контекстный менеджер автоматически закрывает файл даже при возникновении исключения.
* **Зачем `encoding="utf-8"`?** Для корректной работы с кириллицей. Без этого русские буквы могут превратиться в «кракозябры».
* **Почему в `main.py` `except json.JSONDecodeError` стоит раньше `except ValueError`?** Так как `JSONDecodeError` является подклассом `ValueError`, при обратном порядке он перехватил бы ошибку парсинга JSON, и мы бы не смогли вывести специфичное сообщение о поврежденном файле.
* **Зачем нужна проверка `type(x) is int`, а не `isinstance(x, int)`?** В Python `bool` является подклассом `int`. Если использовать `isinstance`, то значение `id=True` пройдет проверку как число, что нарушит ТЗ.
* **Почему `leaders.json` и `selected.json` открываются в режиме `"w"` только внутри блока `else`?** Если входной файл `todos.json` окажется битым, программа выбросит ошибку и не дойдет до записи. Это гарантирует, что старые результаты не будут стерты при неудачном запуске.
